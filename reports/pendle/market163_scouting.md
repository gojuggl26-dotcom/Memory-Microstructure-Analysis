## 3. ★新規: 市場は正しく価格づけていたか(満期まで走った市場でしか測れない)

既存分析の `net` は **時価**(約定後 Δ 秒の中値変化)であって、
**満期まで持った場合の実現損益ではない**。163 は決済 136 回が揃うので、
「市場が設定した固定金利」と「実際に払われた変動金利」を直接比べられる。

| | 値 |
|---|---:|
| implied(mid APR)の時間平均 | **+2.59%**(中央 +3.17%、範囲 −3.43% 〜 +7.20%) |
| **実現(settlement)の平均** | **+2.05%**(中央 +2.79%、範囲 **−36.68% 〜 +17.74%**) |
| **★差(固定 − 変動)** | **+0.54 pp/年**(中央値ベース +0.38 pp) |

> **市場はほぼ正しく価格づけていた。**固定金利は実際に払われた変動金利より
> **年率 0.54pp 高いだけ**で、決済が −36.7% 〜 +17.7% と振れることを考えれば
> **雑音の中に埋もれる大きさ**である。**収穫できる系統的なキャリーは無い。**

補足:
- **決済の 31.6%(43/136 回)が負**。ファンディングは頻繁に符号を変える
- 平均(+2.05%)が中央値(+2.79%)より低いのは最小値 −36.68% の影響。
  **中央値だけで見てはいけない**(METHODOLOGY §5-C-11)
- 各時点で SHORT を建て満期保有した概算では、**正になるのは 57.4%(617/1,075 時点)**、
  中央値 +0.030 pp・年 = 1 YU あたり **+0.0003 BTC**

**私の当初の見立ては外れた。** API の `midApr` 6.98% と `floatingApr` 7.23% を見て
「大きなキャリーがあるはず」と考えたが、あれは**満期直後の 1 時点の値**であり、
全寿命の時間平均は 2.59% 対 2.05% だった。**1 時点を寿命の代表にしてはいけない。**

## 5. ★作業中に起こした事故と復旧(記録)

`scripts/mm_pnl.py` を 163 に対して走らせたところ、
**別セッションの成果物 `reports/mm_summary.parquet`(13 市場の横断結果)を上書きし、
163 の 1 行だけにしてしまった。**

- 原因: このスクリプトは `--markets` に渡した市場だけでサマリを**毎回書き直す**設計。
  実行前にスクリプトの出力先を確認していなかった
- **復旧済み**: 元の 13 市場 + 163 の計 14 市場で `--horizons 3600,86400`(元と同じ)で
  再実行し、**18 列・14 行**で元のスキーマを完全に復元した。検証済み
- **無傷だったもの**: `mm_fills_*.parquet`(13 ファイル)は `--out` を別名にしたため無事。
  `mm_feasibility.md` も無編集
- **教訓**: 他セッションの成果物があるディレクトリでスクリプトを走らせる前に、
  **書き込み先を読む**
