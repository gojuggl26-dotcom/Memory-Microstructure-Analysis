# xyz:MU 日次平均 OI と出来高(2026-05-04 〜 08-10, 99 日)

図: `charts/xyz_MU_oi_volume_usd.png`(名目 USD)/ `charts/xyz_MU_oi_volume_contracts.png`(枚)
数値: `data/daily_oi_volume_xyz_MU.csv`(99 行)
再現: `scripts/fetch_fills.py` → `scripts/build_oi_volume.py` → `scripts/plot_oi_volume.py`

背景の白は米国市場(NYSE)の立会日、薄いオレンジは休場日。休場日はカレンダー
`exchange_calendars` の XNYS から取得しており、**立会 68 日 / 休場 31 日**
(週末 28 日 + 祝日 3 日: 05-25 メモリアルデー、06-19 ジューンティーンス、
07-03 独立記念日の振替)。

## 1. 結果

| | 値 |
|---|---|
| 平均 OI(枚) | 初日 58,511 → 最終日 105,539 / 期間平均 101,960 / 最大 **157,047**(07-30) |
| 平均 OI(名目 USD) | 初日 $33.1M → 最終日 $92.3M / 期間平均 $94.1M / 最大 $133.0M |
| 出来高 | 合計 23,675,483 枚 = **$21.76B** / 1 日平均 $219.8M / 最大 **$846.2M**(07-29) |
| 取引数 | 合計 11,174,755 件 / 参加ユーザー 日次中央値 1,546 人 |
| 復元の不確かさ | 平均 ±1,984 枚 = OI の **±2.0%**(最大 11%) |

枚数ベースの伸び(+80%)と USD ベースの伸び(+179%)が食い違うのは、期間中に
価格が 566 → 874 ドル(+54%)へ上昇したため。**建玉の増加を語るときは枚数、
資金量を語るときは USD** と使い分けること。

## 2. 立会日と休場日の違い

| | 立会日(68 日) | 休場日(31 日) | 比 |
|---|---:|---:|---:|
| 出来高(名目 USD, 平均) | $303.9M | $35.1M | **11.6%** |
| 取引数(平均) | 144,372 | 43,789 | 30.3% |
| 参加ユーザー(平均) | 1,988 | 831 | 41.8% |
| 平均 OI(枚) | 103,236 | 99,162 | 96.1% |
| OI の日次変化 \|Δ\|(終値ベース) | 11,025 枚 | 1,377 枚 | **12.5%** |

**建玉は休場日にほとんど動かない。** 出来高は 1/8.7 に落ちるのに OI 水準は 96% を保ち、
日次の建玉変化の絶対値は 1/8 になる。休場日に起きているのは主に既存ポジションの
持ち回りで、新規の建て落ちは原市場が開いている間に集中している。原資産(Micron)の
価格発見が米国立会時間にしか起きないことの反映であり、**この銘柄を扱う分析は
立会日と休場日を必ず分けること**。曜日ダミーではなく取引所カレンダーを使う
(祝日 3 日が週末と同じ挙動をするため、曜日だけでは取りこぼす)。

## 3. OI をどう作ったか(WORK_BUCKET に建玉のスナップショットが無いため)

`perp_and_spot_balances` を取得していないので、`node_fills` の `startPosition` から
ユーザーごとの建玉推移を復元した。

    pos_before = startPosition
    pos_after  = startPosition + (+sz if side=="B" else -sz)
    OI(t)      = Σ_user max(position, 0)

同一ユーザー・同一 ns に複数 fill があると行順が定まらないので、ns 単位でまとめ、
買い越しなら `entry = min(startPosition), exit = max(pos_after)`、
売り越しならその逆、として入口と出口を決めた。

### 検証

| # | 検証 | 結果 |
|---|---|---|
| V1 | `dir`(Open Long / Close Short / Long > Short …)と (startPosition, side) から導いた向きの一致 | **22,349,510 行すべて一致(100%)** |
| V2 | 多重グループで `exit == entry + Σd` | 片方向グループ(全体の 99.05%)の 98.5% で成立 |
| V3 | 約定を伴わない建玉の飛び | 全 14,312,014 遷移の **0.248%**、Σ\|飛び\| 245,030 枚(総取引量の 0.52%) |
| V4 | 窓開始のネット建玉(理論値 0) | **+2,934 枚**(当時の OI 49,438 枚の 5.9%) |
| V5 | ロング側とショート側を独立に復元したときの食い違い | 平均 ±2.0% / 最大 11%(07-30 に段差) |
| V6 | 外部突合(Hyperliquid 公開 API, 2026-08-27 時点) | 取引所公表 OI = 151,882 枚 / $148.5M。本復元の窓終端(08-10)は 105,539 枚 / $92.3M で、17 日後の公表値と桁・水準が整合 |

### 限界(結論に必ず添えること)

1. **窓期間中に一度も約定しなかったユーザーの建玉は観測できない。** V4 の +2,934 枚が
   その存在量の指標で、窓開始時点の OI の 5.9%。**得られる OI は真値の下限に近い推定**。
2. V3 の「飛び」(ADL・清算まわりと思われる約定を伴わない建玉変化)がロング側と
   ショート側の復元をずらす。図の帯はその半分を不確かさとして描いたもの。
   **2026-07-30 に 14,000 枚の段差**があり、それ以降は帯が広い(〜11%)。
   この日を含む分析では水準の絶対値に依存しない設計にすること。
3. OI は UTC 日の時間加重平均。米国立会時間だけの平均ではない
   (perp は 24 時間動いているため、日全体を覆うのが自然)。
