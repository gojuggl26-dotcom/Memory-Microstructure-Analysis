# ★実現損益による MM 採算の実測検証

[← Derive の分析索引](README.md)

## 何を測ったか

これまで Derive のオプション MM 採算は、板から推定していた
(mark からのエッジ +2.94bp − 逆選択 0.70bp ≒ +3.3bp、ヘッジ費用 4.2bp で赤字)。
本報告は推定をやめ、**取引所が確定させた実現損益**で直接検証する。

  損益 = オプションの反対売買(`realized_pnl`)
       + 満期決済(`option_settlement_pnl`)
       + **perp の反対売買**(デルタヘッジ)
       [+ 残存建玉の時価 — 未実現なので主判定に含めない]

標本: **2024-01-11 〜 2026-09-12(33 か月・976 取引日)**、
オプション約定 1,202,681 行、perp 約定 7,044,832 行、満期決済 255,631 件、
ウォレット 11,699。通貨は BTC / ETH / HYPE / SOL / ZEC。

## 統計の単位と対照

- 対照は「**何もしない = 損益 0**」。判定は「総額 > 0 か」
- **メイカー主体**の定義は結果を見る前に固定: メイカー約定が 7 割以上 かつ 200 約定以上 → **41 ウォレット**
- bp は**名目**(数量 × index)で割る。プレミアムではない
- 日単位ブートストラップ(同じ日の全ウォレットをまとめて再抽出、5,000 回)

## 1. 結論 — 点推定は黒字だが、**成立しているとは言えない**

![実現損益による MM 採算](../../charts/derive_mm_pnl.png)

| 量 | 値 |
|---|---:|
| メイカー主体 41 ウォレットの実現損益 | **+$7,327,909** |
| オプション名目 $7.20B に対して | **+10.18 bp** |
| オプション + perp 名目 $8.92B に対して | +8.22 bp |
| 「何もしない」(=0)との比較 | **勝ち** |
| 日ブートストラップ 95%CI | **[−$8.79M, +$25.20M]** |
| **P(総額 > 0)** | **0.801** |

**★しかしこの黒字は少数の観測に支配されている。**

| 除外するもの | 合計 |
|---|---:|
| なし | **+$7,327,909** |
| 絶対値が大きい 1 日 | +$3,710,955 |
| 同 3 日 | **−$1,982,134** |
| 同 10 日 | **−$1,469,007** |
| 最良の月(2026-09) | +$1,057,706 |
| 最良 2 か月(2026-09, 2026-05) | **−$3,631,249** |

| 代表値 | 値 |
|---|---:|
| 日次の中央値 | **−$5** |
| ウォレット別の中央値 | **−$714** |
| 黒字の日 | 487 / 976(49.9%) |
| 黒字のウォレット | 17 / 41 |
| 黒字の月 | 20 / 33 |

**上位 3 ウォレットだけで +$7,577,316 = 全体の 103%。**残り 38 ウォレットは
合計 **−$249,407** で赤字。つまり総額の黒字は「3 者が稼ぎ、残りはほぼ相殺」である。

したがって主張できるのは:

> **一部の参加者は確かに儲けている。しかし「オプション MM は儲かる商売だ」とは
> このデータからは言えない。典型的な日も典型的な参加者も赤字で、
> 集計の黒字は少数の日と少数の参加者に依存している。**

「有意でない」と「効果がない」は違う。P(>0)=0.801 は**黒字を否定していない**が、
慣用的な水準には届いていない。976 日あってこの区間幅なのは、
日次の振れが大きい(最悪 −$2.35M / 最良 +$3.62M)ためである。

## 3. 月次 — 振れが大きく、少数の月が全体を決める

黒字は 20/33 か月。しかし振れ幅は −$3.83M(2026-06)〜 +$6.27M(2026-09)。
**2026-09 は 12 日しかないのに +$6.27M** で、その 78% が 9/01・9/02・9/04 の
3 日に集中し、いずれも perp 由来である。

| 日 | 合計 | オプション売買 | 満期 | perp |
|---|---:|---:|---:|---:|
| 2026-09-01 | +$1,855,694 | −$841,986 | −$11,611 | **+$2,709,291** |
| 2026-09-02 | +$2,365,480 | −$81,988 | +$8,046 | **+$2,439,422** |
| 2026-09-04 | +$1,318,242 | −$23,279 | +$388,309 | **+$953,211** |

これは MM の定常的な収益ではなく、**方向性のある相場で perp 建玉が当たった**
形に見える。MM の採算として読むべきではない。

## 4. データの作り方(再現と検証)

### 意味論を実測で確定させた

`realized_pnl_excl_fees` = **平均取得単価に対する約定ごとの実現損益(手数料前)**。
`ETH-20260911-2600-C` / subaccount 51031 の**全 194 約定を独立に再生**して
**非ゼロ行 10/10 で完全一致**(合計差 −0.00)を確認した。
★期間途中から再生すると合わない。必ずその銘柄の初回約定から追う。

### 満期決済を落とすと結論が変わる

オプションの建玉は**反対売買か満期決済**でしか終わらない。
`realized_pnl` だけだとメイカー −$6.1M / テイカー +$13.3M と符号が不自然に非対称になる。
実際、上記 subaccount は当該銘柄を **−1,082.9 のまま満期に持ち込んでいた**。

### 満期決済 API の穴を埋めた

`get_option_settlement_history` は **ページ境界で重複を返す**
(page1∩page2 = 35、page2∩page3 = 76 を実測)。重複が出るなら取りこぼしも起きる。
刻みを変えた 4 巡の走査(1000 → 997 → 743 → 613)で和集合を取り、
**226,385 → 253,291 件**(+26,906、初回の単発取得は 10.3% を落としていた)。

さらに**古い満期ほど欠落する**(2024-06〜08 で 27%、2026-09 は 0.4%)。
自前で計算して埋めた:

> 決済損益 = 建玉 × (本源的価値 − 平均取得単価)

この式が API の値を **95.83%(203,223 件)で再現する**ことを確認した上で、
API に無い 30,815 件を補完。平均単価が再生できない 334 件は落とした。

### 独立な完全性検査

API の申告件数に頼らず、自前のデータだけで欠損を炙り出した:
「満期済みで残高が残っているなら決済記録が必ずあるはず」。
この検査で欠落率の時間依存が判明し、補完の必要性が確定した。

## 5. 自己精査

1. **★推定と実測が食い違った。推定が間違っていた。**
   板からの推定では「エッジ +3.3bp をヘッジ費用 4.2bp が食う」と結論したが、
   実測では perp が利益の源泉だった。推定が外した理由は 2 つある:
   (a) ヘッジを**費用**としてしか見ず、perp 側でもメイカーとしてスプレッドを
   取れることを勘定に入れていなかった。実際 `0x3bf64B8c8c` の perp 約定は
   **544,533 件**で、これはヘッジというより perp の MM そのものである。
   (b) 満期決済を勘定に入れていなかった(+$3.40M)。
   **→ 以前の「テイカーでヘッジすると赤字」という結論は撤回する。**
2. **費用を全部引いたか。** `realized_pnl` は手数料差引後。
   手数料 $546,353 支払・リベート $221,402 受領は別建てで開示した
3. **分母を明示した。** オプション名目 $7.20B / perp 名目 $1.72B。
   両方の分母で bp を出した(+10.18 / +8.22)
4. **中央値だけでなく最悪値も。** 日次中央値 −$5、最悪日 −$2.35M、
   ウォレット中央値 −$714 を本文に出した
5. **少数の異常が結論を支配していないか検査した。** §1 の除外表がそれで、
   3 日を除くと符号が反転する。**これを出さずに「+10.18 bp で黒字」と
   書いていたら誤報だった**
6. **未実現を混ぜていない。** 残存建玉の含み −$7.11M は別欄

### この検証が答えていないこと

- **venue 外のヘッジは観測できない。** 41 ウォレット中 16 は Derive 上で
  perp を取引していない。Binance や Deribit でヘッジしている可能性があり、
  その損益は原理的に見えない。**ここで測れるのは「Derive 上で見える損益」に限る**
- **手数料ティアの実態は不明。** メイカー約定の 87% が手数料ゼロだが、
  その 10 ウォレットが何をして資格を得たのかは公開情報から判らない
- **新規参入者の損益ではない。** 測ったのは既存参加者の実績であり、
  1bp の手数料を払う新規が同じ成績を出せるかは別問題
- **RFQ 経由(出来高の 32〜48%)の建玉も含まれる。**板だけの MM とは条件が違う

## 再現手順

```bash
# データ(E:\Derive-options 側)
uv run --with zstandard python scripts/backfill_trades.py --all              # オプション約定
uv run --with zstandard python scripts/backfill_trades.py --type perp --all  # perp 約定
uv run --with zstandard python scripts/fetch_settlements.py --passes 4       # 満期決済
# 分析(このリポジトリ側)
uv run --with zstandard --with polars python scripts/derive_ledger.py        # 損益台帳
uv run --with zstandard python scripts/derive_settle_check.py                # 完全性検査
uv run --with polars python scripts/derive_mm_pnl.py                         # 採算検証
uv run --with polars python scripts/derive_mm_plot.py                        # 図
```

★`derive_ledger.py` は perp をファイル単位で集計する。
全行を辞書で持つと 8GB を超えて OOM する(RAM 15.3GB の機で実際に空き 0.2GB まで落ちた)。
