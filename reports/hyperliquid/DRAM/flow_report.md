# 注文フロー強度 — λ_cancel(Bid/Ask 別)と新規注文強度差

対象: `xyz:DRAM / USDC`(Hyperliquid HIP-3)、2026-05-04 〜 2026-08-10(99 日)
標本: 全注文 446,867,553 件。うち板に載ったもの 343,703,060 件、
そのうち取消で終わったもの 340,236,484 件(99.0%)
作成日: 2026-08-14

---

## 1. 定義

```
λ_cancel^bid = (窓内に取り消された買い注文の残量合計) / Δt      [数量/秒]
λ_cancel^ask = (窓内に取り消された売り注文の残量合計) / Δt
λ_new^buy    = (窓内に板へ載った買い注文の数量合計)   / Δt
λ_new^sell   = (窓内に板へ載った売り注文の数量合計)   / Δt

cancel_ratio          = λ_cancel^bid / (λ_cancel^bid + λ_cancel^ask)
new_intensity_diff    = λ_new^buy − λ_new^sell
cancel_intensity_diff = λ_cancel^bid − λ_cancel^ask     ← 比較用に追加(§4)
```

窓幅は 100ms / 1s / 10s / 60s の 4 通り。
λ は窓幅で割ってあるので、単位はすべて「数量/秒」で窓幅によらず比較できる。

### 情報源と除外規則

L2 の注文ライフサイクル表(注文 1 件 = 1 行)を使う。

- 新規 = `ts_open`、数量 = `orig_sz`
- 取消 = `ts_close` かつ終端が取消系、数量 = `orig_sz − filled_sz`(取消時点の残量)

板に載らなかった注文は除外した。除外しないと「注文フロー」ではなく
「注文の試行フロー」を測ることになる。

| 除外対象 | 理由 | 件数(全期間) |
|---|---|---|
| `is_rejected` | 取引所に拒否され板に載っていない<br>(`perpMarginRejected` / `badAloPxRejected` / `iocCancelRejected` 等) | 内訳は下記 |
| 非滞留 TIF(`Ioc` / `FrontendMarket` / `LiquidationMarket`) | そもそも板に留まらない | 同上 |
| トリガー注文(`is_trigger`) | 発火前は板に無い | 同上 |
| — | 残った「板に載った注文」 | 343,703,060 / 446,867,553(76.9%) |

取消率 99.0% は、この市場が Alo(post-only)の値洗いで回っていることを示す。
1 注文あたりの平均寿命が短く、板の見た目の厚みは頻繁に置き換わっている。

  (取消率 99% の裏返し)

  平均は 4% でしかなく、水準としては小さい

## 4. ★ 比にすると符号が消える

次窓の中値リターン($\log m_{T+2\Delta} - \log m_{T+\Delta}$、先読みなし)との相関、
日次推定の中央値。括弧は 99 日中「符号が逆だった日数」。

| 系列 | 100ms | 1s | 10s | 60s |
|---|---|---|---|---|
| `cancel_ratio`(指定の比) | +0.0022(34) | +0.0008(47) | +0.0005(46) | +0.0049(44) |
| `cancel_intensity_diff`(差) | −0.0184(84) | −0.0188(80) | +0.0041(44) | −0.0008(49) |
| $\lambda^{b}_{\mathrm{cxl}}$ 単独 | −0.0091(81) | −0.0073(72) | +0.0055(40) | +0.0156(34) |
| $\lambda^{a}_{\mathrm{cxl}}$ 単独 | +0.0096(16) | +0.0074(30) | +0.0044(39) | +0.0163(38) |
| `new_intensity_diff` | +0.0028(39) | +0.0170(27) | +0.0144(30) | +0.0050(43) |

読み取れること

1. 符号は理論どおり。 買い注文の取消が増えると価格は下がり($\lambda^{b}_{\mathrm{cxl}}$ は負、
   100ms で 99 日中 81 日が負)、売り注文の取消が増えると価格は上がる
   ($\lambda^{a}_{\mathrm{cxl}}$ は正、99 日中 83 日が正)。両側が逆符号なのは
   「板が消えた側へ価格が動く」という素直な関係
2. しかし比 `cancel_ratio` にすると符号が消える(+0.002、99 日中 47 日が負 = ほぼコイン投げ)。
   一方、同じ情報を差で取った `cancel_intensity_diff` は −0.019 で 80/99 日が負と一貫する。
   理由は比が水準を捨てること。取消が毎秒 100 のときの 0.6 と、毎秒 100,000 のときの 0.6 は
   板に与える衝撃がまったく違うのに、比は同じ値を返す。
   $\frac{\lambda^{b}_{\mathrm{cxl}}}{\lambda^{b}_{\mathrm{cxl}}+\lambda^{a}_{\mathrm{cxl}}}$ を使うなら、総取消強度を別の変数として
   併用しないと情報が落ちる。
3. 新規注文の強度差は 1〜10 秒で効く(+0.017 / +0.014、99 日中 72 / 69 日が正)。
   取消は 100ms〜1s、新規は 1〜10s と効く時間帯が違う。
   取消は即座に板を消すのに対し、新規注文は積み上がってから効くという解釈と整合する
4. 大きさはいずれも相関 0.02 未満。単独のシグナルではなく、部品として扱う水準
   (`regression_report.md` §6 と同じ結論)

## 5. 検証

| 項目 | 結果 |
|---|---|
| 板に載った注文の内訳 | 343,703,060 / 446,867,553(76.9%)。除外は棄却・非滞留 TIF・トリガー |
| 取消で終わった注文 | 340,236,484(板に載ったものの 99.0%) |
| 取消数量が負になる行 | 0 件(`orig_sz − filled_sz` を 0 で下限クリップ) |
| `cancel_ratio` の値域 | [0, 1]。両側 0 の窓は null |
| λ の単位 | すべて数量/秒。窓幅で割ってあるので窓間で直接比較できる |

注意: 取消数量は「取消時点の残量」であって発注時の数量ではない。
部分約定後に取り消された注文では両者が違う。発注数量ベースが必要なら
`vol_new_*` と突き合わせること。
