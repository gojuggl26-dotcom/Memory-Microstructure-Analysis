## 1. 定義と情報源

「1 イベント」= 最良気配 `(best_bid, best_ask, bid_sz, ask_sz)` が変化した瞬間(ns 精度)。

| # | 系列 | 定義 | 粒度 |
|---|---|---|---|
| 1 | `bid_ask_spread` | `price_ask − price_bid` | 1 イベント |
| 2 | `order_imbalance` | `(Volume_buy − Volume_sell) / (Volume_buy + Volume_sell)` | 固定時間窓(§5) |
| 3 | `depth_one_level` | `(Quantity_bid − Quantity_ask) / (Quantity_bid + Quantity_ask)` | 1 イベント |
| 4 | `voi` | $\Delta Q^{b}_{t} - \Delta Q^{a}_{t}$ | 1 イベント |

### (4) VOI — t−1 と t の最良気配から決める

`ΔQuantity` は価格と数量の両方を t−1 と t で比べて決める(Shen 2015)。

```
ΔQ^b_t = 0                     (P^b_t < P^b_{t−1})   気配が下がった → 旧レベルは消滅済み
       = Q^b_t − Q^b_{t−1}     (P^b_t = P^b_{t−1})   同じ価格なら素の差分
       = Q^b_t                 (P^b_t > P^b_{t−1})   気配が上がった → 全量が新規

ΔQ^a_t = 0                     (P^a_t > P^a_{t−1})
       = Q^a_t − Q^a_{t−1}     (P^a_t = P^a_{t−1})
       = Q^a_t                 (P^a_t < P^a_{t−1})

VOI_t = ΔQ^b_t − ΔQ^a_t
```

価格を見ずに数量だけ引き算すると、気配が動いた瞬間に別の価格水準の数量を引く。
このデータではイベントの 82.4% で最良気配の価格が動くので、これは例外ではなく常態である。
比較用に素の差分版を `voi_raw_diff`、Cont-Kukanov-Stoikov 版(気配が不利に動いた時に
0 ではなく `−Q_{t−1}` を使う)を `ofi_cont` として併記した。

### (2) 約定インバランス — 情報源が板ではない

`Volume_buy` / `Volume_sell` は板の数量ではなく約定量なので、`node_fills` を使う。
方向はテイカー(`crossed = True` の行)の side で決める
(1 取引はメイカー/テイカーの 2 行で入るため、テイカー行のみ)。
粒度は §5 のとおり固定時間窓とした。

## 5. 約定インバランスの窓幅 — 「最狭」は最良ではない

イベント単位だと、約定のあるイベントは全体の 12.2% しかなく、
そのうち 59.7% は約定 1 件のみ → OI の 97.8% が ±1 に貼り付く符号変数になる。
そこで固定時間窓ごとに作り直した。窓幅の下限は fills の時刻分解能である 1ms。

| 窓 | 窓数 | 1 窓あたり取引数 | ±1 飽和率 | 同窓の相関 | 次窓の相関 | 次窓で符号逆の日 |
|---|---|---|---|---|---|---|
| 1 ms | 2,863,698 | 2.08 | 97.8% | 0.113 | 0.006 | 2 / 99 |
| 10 ms | 2,863,687 | 2.08 | 97.8% | 0.344 | 0.004 | 20 / 99 |
| 100 ms | 2,788,134 | 2.14 | 97.3% | 0.349 | 0.039 | 4 / 99 |
| 1 s | 1,893,395 | 3.15 | 85.5% | 0.332 | 0.077 | 4 / 99 |
| 10 s | 560,566 | 10.6 | 48.5% | 0.306 | 0.030 | 6 / 99 |
| 60 s | 127,579 | 46.7 | 20.8% | 0.305 | 0.025 | 21 / 99 |

飽和率は窓加重。相関は日次推定の中央値。「次窓」= 窓が閉じた後の 1 窓分のリターン
($\log m_{T+2\delta} - \log m_{T+\delta}$)に対する相関で、先読みを含まない。
「同窓」は窓の中で同時に起きた値動きとの相関で、因果ではなく機械的な同時性を見ている。

わかったこと

1. 1ms まで細かくしても ±1 飽和は解けない(97.8%)。原因は窓幅ではなく市場の構造で、
   1 件の成行注文が同一ミリ秒に複数の約定を生み、それらはすべて同じ方向だから。
   実際 1ms と 10ms で窓数がほぼ同じ(2,863,698 vs 2,863,687)= 約定は時間軸上で疎に束になっている
2. 飽和が実質的に解けるのは 10s 以降(48.5% → 60s で 20.8%)
3. しかし予測力が最大なのは 1 秒窓(次窓相関 0.077)。10s / 60s では 0.03 前後に落ちる。
   飽和が解けた頃には情報も薄まっている
4. 最狭(1ms・10ms)は次窓をまったく当てない(0.006 / 0.004)。
   同窓相関が 0.11 → 0.34 と高いのは「その窓の中で価格が動いた」という機械的同時性であって、
   予測ではない

結論: 使うなら 1 秒窓。±1 飽和が 85% 残るので連続量としては扱えず、
「直近 1 秒の約定が買い優勢か売り優勢か」という強い符号変数として扱うのが正しい。
全 6 通りを出してあるので、用途に応じて選べる。

### `data/DRAM/features` の列

| 列 | 内容 |
|---|---|
| `ts` | イベント時刻(UTC ns) |
| `best_bid` / `best_ask` / `bid_sz` / `ask_sz` | 入力(板の最良気配) |
| `bid_ask_spread` | (1) `price_ask − price_bid`(USDC)。`bid_ask_spread_bp` も併記 |
| `depth_one_level` | (3) |
| `d_vol_bid` / `d_vol_ask` | (4) の `ΔQuantity`(t−1/t 最良気配の規則を適用済み) |
| `voi` | (4) 採用版 |
| `voi_raw_diff` / `ofi_cont` | 比較用の 2 定義 |
| `vol_buy` / `vol_sell` / `n_trades` / `order_imbalance` | イベント区間の約定(参考。推奨は `oi_grid`) |
| `is_crossed` | 統計では除外すること(`regression_report.md` §2) |

### `data/DRAM/oi_grid` の列

`ts`(窓の開始・UTC ns)/ `vol_buy` / `vol_sell` / `n_trades` / `order_imbalance`。
約定のあった窓のみを行にしている(空の窓は存在しない)。

### 再現手順

```bash
uv run python scripts/build_features.py <出力先>   # 約 6 分
uv run python scripts/features_summary.py
uv run python scripts/build_oi_grid.py <出力先>    # 約 2 分
uv run python scripts/oi_grid_summary.py
```
