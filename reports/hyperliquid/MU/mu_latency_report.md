# xyz:MU — 約定 δ ミリ秒前の標本外 AUC と、実際に取り消せる速さ

図: `xyz_MU_latency.png`

![xyz MU latency](../../../charts/xyz_MU_latency.png)

「約定の δ ミリ秒前に、その約定が toxic になると判るか」を
δ = 500 / 250 / 100 / 50 / 20 / 10 ms で測り、**その横に実際の取り消し往復遅延**を置く。
標本 588,000 約定(1 日 1 側あたり最大 3,000 を無作為抽出)、
学習 59 日 / 評価 39 日の**時間で前後に切った標本外**。

---

## 0. 結論を先に

| | |
|---|---|
| **標本外 AUC は δ を詰めると上がるが 50 ms で飽和**(0.555 → 0.590) | 下の表 |
| **50 ms より内側は板が動いていない** — 50→20 ms で 99.6%、20→10 ms で **100.0%** が同一 | データの時間分解能そのもの |
| **ブロックは 65 ms 周期**。任意の時点から次の板更新までの待ちは**中央値 185 ms** | 実測 |
| **実際に 50 ms 以内に取り消せている注文は 0.01%**(同一ブロック内の一括取消を除く) | 実測 |
| → **使える δ は 185 ms 以上**。そこでの AUC は **0.555〜0.577** | |
| **10 変数の多変量モデルは OFI(1秒)単独とほぼ同じ**(δ≤100ms で差 +0.0005〜0.001) | |
| **その AUC で上位 50% を取り消しても markout の改善は +0.267 bp**、黒字化に必要な +1.031 bp に 1.73 bp 届かない | |

## 1. 標本外 AUC

目的変数は「約定後 10 秒の markout(損益の向き)が**その日の下位 20%**」。
符号は学習期間で決め、評価期間に当てている。

| 指標 | 500ms | 250ms | 100ms | 50ms | 20ms | 10ms |
|---|---:|---:|---:|---:|---:|---:|
| **OFI (1秒)** | **0.5438** | **0.5726** | **0.5858** | **0.5894** | **0.5898** | **0.5900** |
| OFI (100ms) | 0.5181 | 0.5614 | 0.5456 | 0.5483 | 0.5344 | 0.5317 |
| OBI | 0.5181 | 0.5415 | 0.5489 | 0.5527 | 0.5528 | 0.5528 |
| T からの値動き | 0.5106 | 0.5263 | 0.5353 | 0.5371 | 0.5371 | 0.5376 |
| 経過時間 | 0.5222 | 0.5222 | 0.5222 | 0.5222 | 0.5222 | 0.5222 |
| スプレッド | 0.5214 | 0.4955 | 0.4967 | 0.4964 | 0.4964 | 0.4964 |
| 待ち行列の消化 | 0.5094 | 0.5129 | 0.5156 | 0.5186 | 0.5189 | 0.5189 |
| 自分側の厚み | 0.5140 | 0.5064 | 0.5042 | 0.5031 | 0.5029 | 0.5030 |
| 攻撃的流量 (1秒) | 0.5073 | 0.5091 | 0.5141 | 0.5176 | 0.5161 | 0.5165 |
| 攻撃的流量 (100ms) | 0.5023 | 0.5035 | 0.5066 | 0.5110 | 0.5074 | 0.5072 |
| **★ 多変量 (ロジット 10 変数)** | **0.5549** | **0.5770** | **0.5859** | **0.5904** | **0.5906** | **0.5905** |
| (参考) 多変量の学習期間 AUC | 0.5547 | 0.5795 | 0.5857 | 0.5888 | 0.5887 | 0.5888 |

- **学習と評価がほぼ一致**しており、過学習はしていない
- **多変量は OFI(1秒)単独をほとんど超えない。** 差は 500ms で +0.0112、
  250ms で +0.0044、100ms 以下では **+0.0001〜0.0010**。
  10 変数を使う意味はほぼ無い
- 前の報告([3 分解と事前兆候](mu_markout_report.md))の単変量 AUC 0.452
  (= 符号を揃えると 0.548)と整合する

### なぜ 50 ms で飽和するのか — 板が動いていないから

| 比較 | 板の状態が同一の割合 |
|---|---:|
| 500ms → 250ms | 26.4% |
| 250ms → 100ms | 46.3% |
| 100ms → 50ms | 73.2% |
| **50ms → 20ms** | **99.6%** |
| **20ms → 10ms** | **100.0%** |

**δ = 10 ms で測ることは δ = 50 ms で測ることと同じである。**
モデルの限界ではなく、データの時間分解能の限界である。
なお 500ms → 10ms の間に板が一度も動かなかった約定が **19.2%** ある。

## 2. 実際に取り消せる速さ

### ブロックは約 65 ms 周期

板更新の間隔は **65.2 ms の整数倍**にきれいに並ぶ。

| 間隔 | 割合 |
|---|---:|
| 5 ms 未満(同一ブロック内の別イベント) | 5.85% |
| 約 65 ms(1 ブロック) | **26.81%** |
| 約 130 ms(2 ブロック) | 14.11% |
| 約 196 ms(3 ブロック) | 8.42% |
| 約 261 ms(4 ブロック) | 2.40% |
| 約 326 ms(5 ブロック) | 1.39% |

つまり**行動の下限は 1 ブロック = 65 ms**(これに通信の往復が乗る。
通信遅延はこのデータからは測れない)。

### 情報が来る間隔と、次の更新までの待ち

| | p10 | p25 | **p50** | p75 | p90 |
|---|---:|---:|---:|---:|---:|
| 板更新の間隔 | 62 | 68 | **131** | 208 | 404 ms |
| **任意の時点から次の更新までの待ち** | 26 | 64 | **185** | 694 | **2,643** ms |

待ち時間は長さで重みづけられるので、間隔の中央値(131 ms)より長い
**185 ms** になる。「今この瞬間に何かを知りたい」と思っても、
半分の場合は 185 ms 待たないと板は動かない。

### 参加者が実際に取り消せている速さ

取消の累積発生率(**10.26% は同一ブロック内**で、L4 では時間を解像できない。
一括取消などと考えられるので下段では除いてある)。

| 発注からの経過 | 同一ブロックを含む | **同一ブロックを除く** |
|---|---:|---:|
| 10 ms | 10.26% | **0.00%** |
| 20 ms | 10.27% | **0.00%** |
| **50 ms** | 10.27% | **0.01%** |
| 100 ms | 16.40% | 6.84% |
| 250 ms | 22.25% | 13.36% |
| 500 ms | 33.23% | 25.60% |
| 1,000 ms | 60.38% | 55.85% |

**この市場で 50 ms 以内に取り消せている注文は事実上 存在しない。**
最速の参加者でも 65〜100 ms かかっている。

## 3. 突き合わせ — 使える δ とその AUC

| δ | 標本外 AUC(多変量) | 取り消しは間に合うか |
|---|---:|---|
| 500 ms | 0.5549 | **間に合う**(25.6% が実際に取り消せている) |
| 250 ms | 0.5770 | **ほぼ間に合う**(13.4%。待ちの中央値 185 ms を超える) |
| 100 ms | 0.5859 | 苦しい(6.8%。1〜2 ブロック分しかない) |
| 50 ms | 0.5904 | **不可能**(0.01%) |
| 20 ms | 0.5906 | 不可能。かつ板は 50 ms 前と 99.6% 同一 |
| 10 ms | 0.5905 | 不可能。かつ板は 20 ms 前と 100% 同一 |

**δ を 250 ms から 10 ms へ詰めて得られる AUC は +0.0135 だけで、
その全部が手の届かない領域にある。**

---

## 4. その AUC で取り消したらどうなるか

δ = 250 ms(間に合う最速)の標本外スコアで、toxic 度の上位 X% を取り消す。

| 取消割合 | 残る約定 | 残りの markout | 改善 |
|---|---:|---:|---:|
| 0% | 234,000 | −0.966 bp | — |
| 5% | 222,300 | −0.924 | +0.042 |
| 10% | 210,600 | −0.891 | +0.075 |
| 20% | 187,200 | −0.832 | +0.134 |
| 30% | 163,800 | −0.781 | +0.185 |
| **50%** | 117,000 | **−0.699** | **+0.267** |

クオート寿命 10 秒での実際の優位は −0.943 bp、手数料 0.088 bp なので、
残った約定が黒字になるには **markout ≥ +1.031 bp** が要る。
**上位半分を捨てても −0.699 bp で、まだ 1.73 bp 足りない。**

改善が取消割合にほぼ比例している(5% で +0.042、50% で +0.267)のは、
スコアの分離が弱いこと(AUC 0.577)の裏返しである。

## 5. 結論として何が言えるか

1. **取り消しで toxic を選り分けることはできない。** 間に合う最速の
   δ = 250 ms で AUC 0.577、上位半分を捨てても markout は 0.27 bp しか改善しない
2. **速くしても意味がない。** 50 ms より内側は板が動いておらず、
   情報が増えない。しかも 50 ms では実際に取り消せない
3. **効くのは選り分けではなく寿命である。**
   [3 分解の報告](mu_markout_report.md)のとおり、クオートの寿命を
   10 秒から 100 ミリ秒に縮めると A(置いている間の劣化)は
   −1.618 → −0.007 bp と 1.6 bp 動く。これは選り分けで得られる
   0.27 bp の 6 倍である
4. **ただし寿命 100 ミリ秒は「取り消して出し直す」では実現できない。**
   1 ブロック 65 ms なので、100 ms の寿命とは「出して 1〜2 ブロックで引く」
   ことであり、実質的には毎ブロック出し直すことを意味する

---

## 6. 言えないこと

- **通信の往復遅延を測っていない。** ここで出したのはブロック周期(65 ms)と
  板更新の間隔だけで、自分の注文が取引所に届くまでの時間は
  このデータからは判らない。実際の往復はこれより長くなる
- **同一ブロック内の取消 10.26% の中身は判らない。** 時間を解像できないので、
  「速い」のか「まとめて出した」のかを区別できない
- **toxic の定義は「その日の下位 20%」である。** 閾値を変えれば AUC も変わる
- **1 日 1 側あたり 3,000 件に間引いている。** 間引きは目的変数と無関係な
  無作為抽出で、AUC の推定に偏りは入らないが、精度は全数より落ちる
  (評価 234,000 件なので AUC の標準誤差は 0.002 程度)
- **待ち行列は取り消しによる繰り上がりを数えていない**(既報と同じ)
- **銘柄は xyz:MU のみ**、標本 97 日
