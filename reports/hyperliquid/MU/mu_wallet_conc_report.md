# xyz:MU 板の数量は何者の口座に集まっているか(wallet concentration)

[← xyz:MU 分析索引](README.md)

1 秒ごとに板を復元し、その瞬間に数量を置いている口座ごとの残高からシェアを作って
集中度を測る。標本は 2026 年 5 月 4 日から 8 月 9 日の 98 日、
**1 秒格子 846 万点**(立会日 67 日 / 閉場日 31 日)。

再現: `scripts/fetch_l1.py` → `scripts/fetch_l1_extra.py` →
`scripts/build_wallet_conc.py` → `scripts/plot_wallet_conc.py`

| ⑬ | **touch concentration** | **0.644** | 0.376 | 0.956 |
| ⑭ | **deep-book concentration** | **0.081** | 0.062 | 0.104 |

読みどころは 3 つある。

1. **最良気配は別の市場である。** 板全体の HHI が 0.081(実効 12 者相当)なのに対し、
   最良気配だけを取ると **0.644**。持っているのは平均 **3.17 者**で、
   そこにある数量は板全体の **0.14%** にすぎない。
2. **「板が厚い」のは奥の話である。** deep(最良以外)の HHI は 0.081 で全体と
   ほぼ同じ。数量の 99.86% が最良の外側にあるので、全体の集中度は事実上
   奥の板の集中度である。
3. **売り側のほうが集中している。** concentration imbalance は平均 −0.107。
   買いに数量を置く口座が 242 者に対し売りは 160 者しかいない。

## 2. 定義

各時点で板に数量を置いている口座 $`i`$ の残高を $`Q_i`$ とし、シェアを作る。

```math
w_i = \frac{Q_i}{\sum_j Q_j}
```

```math
HHI = \sum_i w_i^2 \qquad H = -\sum_i w_i \ln w_i \qquad
Gini = \frac{\sum_{k} (2k - n - 1)\, Q_{(k)}}{n \sum_i Q_i}
```

ここで $`Q_{(k)}`$ は昇順に並べた残高であり、n はその瞬間に残高が正の口座数である。
HHI は 1 者独占のとき 1、n 者が均等なら 1/n になる。エントロピーは
実効口座数 $`e^{H}`$ に直して併記した。

| 指標 | 中身 |
|---|---|
| number of active wallets | 買いか売りに数量を置いている口座の数 |
| bid / ask wallet count | それぞれの側に数量を置いている口座の数 |
| BBO wallet count | 最良買・最良売のどちらかに数量を置いている口座の数 |
| concentration imbalance | $`(HHI_{bid} - HHI_{ask}) / (HHI_{bid} + HHI_{ask})`$ |
| touch concentration | 最良気配にある数量だけで測った HHI |
| deep-book concentration | 最良気配以外にある数量だけで測った HHI |

**分母はその瞬間に板にある数量**であって、その日に出された注文の総量ではない。
後者を分母にするのが[束の間の注文](mu_fleeting_report.md)で、両者は別物である。

### なぜ 1 秒格子か

板そのものの状態を測るので、注文の出入りではなく**ある瞬間の残高**を見る。
パイプラインの L2 スナップショットと同じ 1 秒を使う。指値の寿命は中央値 565ms
なので、1 秒格子に写るのは**滞留している注文だけ**である。これは意図した挙動で、
瞬間的に出し入れされる注文は板の厚みとして誰かが取れるものではない。

### 母集団

トリガー注文とテイカー(`Ioc` / `FrontendMarket` / `LiquidationMarket`)を除いた
`Alo` / `Gtc` の指値。**`reduce_only` は板に載るので含める。**
[ハザード](mu_hazard_report.md)や[束の間の注文](mu_fleeting_report.md)では
終端の意味が曖昧なので外したが、板の厚みを数えるここでは、
載っている以上は数えないと実態と合わない。

## 3. ★踏んだ 2 つの落とし穴 — どちらも板が膨らみ続ける

この分析は**再構成した板が壊れていても、指標だけ見れば整合して見える**。
実際に 2 度、板が単調に膨らんだまま「もっともらしい」数字が出た。

### (1) 繰越注文の終端が捨てられていた

`l1user`(oid → 口座)は **`open` 行だけ**を持つ。前日から繰り越した注文の oid は
その日のファイルに無いので、終端行に口座が付かず null として捨てられ、
**その注文は板から永久に消えなくなった。** 活動口座は実測 135〜344 者に対して
**3,041 者**まで積み上がった。carry に (oid, 口座) を足して解決。

### (2) 終端イベントが最後まで現れない注文がある

約定の一部は `filled` を出さない(パイプライン側の実測で取引数量の 29.17%)。
終端が最後まで来ない注文は、(1) を直した後もそのまま板に残り続け、
活動口座は **1,708 者**、繰越は 1,333 → 16,183 本まで増え続けた。

そこで**閾値を決める前に寿命を実測した**。2 日・1,715 万本の指値について、

| | |
|---|---:|
| 終端が観測できた割合 | **99.98%** |
| 寿命 > 1 時間 | 0.019% |
| 寿命 > 6 時間 | 0.006% |
| **寿命 > 24 時間** | **0 本** |
| 観測された最長寿命 | 20.5 時間 |

**24 時間を超えて生きた注文は 1 本も観測されていない。** そこで
**24 時間まったく動きの無い注文は落とす**ことにした。実在するものを
1 本も捨てない足切りである(98 日で 53,842 本、1 日あたり約 550 本を除去)。

### 直った後の検算

| 検算 | 直す前 | **直した後** |
|---|---|---|
| 2026-07-15 の活動口座(直接数えた実測は 135〜344 者) | 1,708 者 | **374 者** |
| 活動口座が前日より増えた日 | 78 / 97 日 | **48 / 97 日** |
| 繰越(中央 / 最大) | 9,822 / 16,978 | **2,098 / 7,293** |
| 最良買の数量が bbo と厳密に一致 | 74.9% | **82.0%** |
| 同じく数量の比 | 1.409 倍 | **1.242 倍** |

最良気配の数量を bbo と突き合わせる検算は、この 2 つのどちらでも必ず壊れる。
**指標だけを見ていては気づけなかった。**

## 4. 結果

### 4.1 口座数

| | 平均 | 立会日 | 閉場日 |
|---|---:|---:|---:|
| active | 313 | 338 | 259 |
| bid | 242 | 261 | 202 |
| ask | 160 | 170 | 136 |
| **BBO** | **3.17** | 3.13 | 3.26 |

板全体には 300 者ほどが数量を置いているのに、**最良気配を持っているのは
常に 3 者前後**である。日内 p10 で 1.92、p90 で 5.04。

買い側の口座数が売り側の 1.5 倍あるのは標本期間を通じて安定している。

### 4.2 集中度

| | 平均 | 日ごとの分布(p0 / p50 / p100) |
|---|---:|---|
| HHI | 0.081 | 0.028 / 0.064 / 0.442 |
| 実効口座数 exp(H) | 37.0 | 6.0 / 36.7 / 75.8 |
| Gini | 0.884 | 0.809 / 0.884 / 0.948 |
| top-1 | 20.0% | 8.9% / 17.9% / 65.8% |
| top-10 | 60.7% | 43.5% / 60.7% / 87.2% |

HHI 0.081 は「均等な 12 者」に相当する。一方エントロピーから作った実効口座数は
37.0 者である。**同じ「実効的な参加者数」でも 3 倍違う。**
HHI は上位に、エントロピーは裾に重みを置くためで、
どちらを使うかで結論が変わる場面では両方を書くこと。

日ごとの幅が大きい(HHI 0.028〜0.442、top-1 8.9%〜65.8%)。
**平均だけで語ってはいけない。** 最も集中した日は 1 者が板の 3 分の 2 を持っていた。

### 4.3 touch と deep

| | HHI | 数量が板に占める割合 |
|---|---:|---:|
| **touch(最良気配)** | **0.644** | **0.14%** |
| deep(最良以外) | 0.081 | 99.86% |
| 全体 | 0.081 | 100% |

**deep は全体とほぼ同じ値になる。** 最良気配にある数量が板全体の 0.14% しか
ないからで、これは計算の検算にもなっている(touch を抜いても分布が動かない)。

touch の HHI は日内 p90 で 0.956 に達する。**最良気配が 1 者に独占されている
時間帯が珍しくない**ということである。

### 4.4 concentration imbalance

平均 **−0.107**(売り側のほうが集中)。日ごとの分布は −0.810 〜 +0.628 と広く、
日内 p10 −0.283 / p90 +0.068。符号は日によって入れ替わるが、
期間全体では売り側に寄る。口座数(買い 242 対 売り 160)と整合する。

### 4.5 立会日と閉場日

| | 立会日 | 閉場日 |
|---|---:|---:|
| active | 338 | 259 |
| HHI | 0.0835 | 0.0758 |
| Gini | 0.890 | 0.869 |
| top-10 | 61.1% | 60.0% |

原資産市場が開く日は参加する口座が増える(259 → 338)のに、
**集中度も上がる**(HHI 0.0758 → 0.0835)。増えた口座は小さく、
大きな口座がさらに大きくなるためである。

## 5. 限界

1. **板の深さは 1.24 倍に過大**(第 3 節の検算)。`filled` イベントを出さない
   約定が原因で、`fills` に `oid` が無い以上この再構成では消せない。
   [ティック水準別 OBI](mu_obi_levels_report.md) と同じ既知の偏りである。
2. **24 時間の足切りは機械的な規則**(第 3 節)。実在する注文を 1 本も捨てない
   ことは実測で確かめたが、**足切りの位置を変えれば口座数は動く**。
   24 時間より短くすれば減る。
3. **口座は `user` の一致で数えている。** 同じ主体が複数の口座を使っていれば
   集中度は過小評価になる。
4. **1 秒格子は滞留している注文しか見ない。** 板を出し入れするだけの参加者は
   ここには現れない。そちらは[束の間の注文](mu_fleeting_report.md)が扱う。
5. **記述統計であって予測ではない。** 集中度が将来の値動きや流動性の枯渇を
   教えるかは一切検証していない。
6. **1 銘柄の記述統計である。** 銘柄横断の比較には他の 5 銘柄の `l1` と
   口座情報が要る。
