# 指値注文はどれだけ生き残るか — 6 つの条件で見た生存率・取消率・約定率

[← xyz:MU 分析索引に戻る](README.md)

板に置かれた指値注文 1 本を「寿命」を持つ個体とみなし、置かれてからの経過時間に対して
**まだ残っている割合(生存率)**、**次の瞬間に取り消される率**、**次の瞬間に約定する率**
を出す。さらにそれらを、発注の瞬間に判っている 6 つの条件で層別する。

| | 条件 | 意味 |
|---|---|---|
| ① | queue | 同じ価格に自分より前に並んでいた数量(契約) |
| ② | size | 自分の注文数量(契約) |
| ③ | dist | 同じ側の最良気配から何ティック離れた場所に置いたか(負 = 気配を改善) |
| ④ | wallet | その口座がそれまでに出した注文の累計本数 |
| ⑤ | vol | 直前 300 秒の mid の実現ボラティリティ(bp) |
| ⑥ | ofi | 直前 1 秒の OFI を「自分の注文へ価格を押し付ける向き」で符号付けした値 |

標本は **2026 年 5 月 4 日〜8 月 9 日の 98 日、549,920,651 本**の指値注文である。

---

## 0. 要点

1. **板に置かれた指値のうち、最終的に約定するのは 0.915% しかない。** 残る 99.08% は
   取り消される。しかも **10.45% は発注と同じブロックのうちに消える**(1 ブロックも
   板に留まらない)。寿命の中央値は **565 ミリ秒**、1 秒後に残っているのは 39.1%、
   60 秒後は 2.2% である。
2. **6 つの条件のうち、約定率を最も大きく動かすのは「口座」である。** その口座にとって
   初めての注文は 57.8% が約定するのに対し、10 万本以上出している口座の注文は 0.713%
   しか約定しない。**81 倍**の開きがある。一方で全注文の 95.1% はその「10 万本以上」
   の口座から出ている。
3. 次に効くのは **注文数量(39 倍)**、**距離(28 倍)**、**キュー位置(4.7 倍)**の順。
   数量は 0.3 契約未満で 3.736%、100 契約以上で 0.095%。距離は気配を改善して置くと
   4.526%、101〜300 ティック奥だと 0.160%。キュー位置は先頭 1.379% 対
   100〜300 契約待ち 0.292% で、3 つのなかでは最も弱い。
4. **ボラティリティの効果は U 字**である。取消ハザードはボラティリティとともに単調に
   上がる(毎秒 0.286 → 0.707)が、約定ハザードは中程度でいちばん低く、静かなときと
   荒れたときの両端で高い。結果として最終約定率は 1.440% → 0.797% → 1.425% となる。
5. **OFI の効果は「短い時間の中だけ」に出る。** 距離を揃えて発注 0.1 秒後の約定ハザードを
   見ると、流れが自分の注文へ向かっている層は逆向きの層の **3.6 倍**(毎秒 0.0574 対
   0.0157)。ところが 1 秒後にはこの差はほぼ消える。最終約定率の差(1.104% 対 0.710%)
   だけを見ると効果を取り違える。
6. これらはすべて**条件付き分布であって因果ではない**(第 8 節)。

## 1. なぜ「率」を 2 通り出すのか

「取消率」「約定率」という言葉は、日常語では 2 つの別のものを指してしまう。

1. **最終的にどうなったか** — その注文が結局は取り消されたのか、約定したのか。
   1 本につき 1 回しか起きない。母集団に対する割合として書ける。
2. **いま生きている注文が、次の瞬間にどうなるか** — これが**ハザード**である。
   単位は「毎秒」。1 秒生き残った注文と 1 時間生き残った注文では、まるで値が違う。

この 2 つは別物で、しかも後者から前者が決まる。本レポートは両方を出す。
**⑥ OFI のように、片方だけを見ると結論が変わる例が実際にある。**

### 競合リスクとして扱う

注文の行き先は「取消」と「約定」の 2 つあり、**どちらかが起きた時点でもう一方は
永久に起こらない**。これを競合リスク(competing risks)という。

ここを雑に扱うと必ず間違える。たとえば「約定を打ち切りとみなして取消の生存曲線を引く」
と、取消しか起きない世界を仮定したことになり、取消の確率を過大に見積もる。逆に
「1 − 生存率」を取消率と呼ぶと、約定した分まで取消に数えてしまう。

正しくは、原因別ハザード

```math
h_k(\tau) \;=\; \lim_{\Delta\to 0}\frac{1}{\Delta}\,
\Pr\!\left[\tau \le T \lt \tau+\Delta,\; K=k \;\middle|\; T \ge \tau\right],
\qquad k \in \{\text{約定},\ \text{取消}\}
```

と、そこから積み上げた累積発生確率

```math
F_k(\tau) \;=\; \int_0^{\tau} S(u)\, h_k(u)\, du,
\qquad S(\tau) = \exp\!\left(-\int_0^{\tau}\!\big(h_{\text{約定}}+h_{\text{取消}}\big)\,du\right)
```

を使う。$`F_{\text{約定}}(\infty)`$ が「最終的に約定した割合」、$`S(\tau)`$ が「生存率」である。
実装は打ち切りを扱える生命表(actuarial)方式で、区間 $`j`$ について

```math
n'_j = n_j - \tfrac{1}{2} c_j,\qquad
\hat q_j = \frac{d^{\text{約定}}_j + d^{\text{取消}}_j}{n'_j},\qquad
\hat h_{k}(j) = \frac{d^{k}_j}{n'_j \,\Delta t_j}
```

($`n_j`$ は区間の開始時点で生きている本数、$`c_j`$ は区間内の打ち切り数、$`\Delta t_j`$ は
区間の幅を秒で表したもの)。

## 2. 母集団と前処理

**板に留まる指値だけ**を数える。次を除く。

| 除くもの | 理由 |
|---|---|
| トリガー注文(`is_trigger`) | 発火するまで板に載らない。板に入れると買いと売りが同時に生存してクロスする |
| テイカー(`tif` が `Ioc` / `FrontendMarket` / `LiquidationMarket`) | 板に留まらないので「置いた指値が生き残るか」の母集団ではない |
| `reduce_only` | 取引所がポジション減少に合わせて自動縮小するため、残量が減っても約定とは限らない(パイプライン側で約定量を 22.8% 過大計上した既知の罠)。ただし**板の厚みには数える**(実際に載っているため) |

終端は `filled` を「約定」、`canceled` ほか 6 種を「取消」とする。標本の末尾でまだ
生きている注文と、取得元の欠測時間帯をまたいだ注文は**右打ち切り**にする。

### ★ ts はブロック時刻である

このデータの `ts` は取引所のブロック時刻で、**同じ `ts` に平均 6.5 行が入り、
隣り合うブロックの間隔は中央値 74.9 ミリ秒**である(2026-05-07 で実測)。したがって

- 寿命はブロック単位に量子化されている。10 ミリ秒より細かいハザードは測れない
  (実測でも寿命 10 ミリ秒未満は 5.5 億本中 6,107 本 = 0.0011% しかない)
- **寿命ちょうど 0 の注文が 10.45% ある**。これは「発注と同じブロックで消えた」注文で、
  1 ブロックも板に留まらなかったことを意味する。毎秒の率としては定義できないので、
  確率質量として別に持ち、図では生存曲線の左端が 1.0 に届かないことで表す

### ★ ティック幅は 0.01 固定ではない

Hyperliquid の価格は有効数字 5 桁なので、**1000 未満は 0.01、1000 以上は 0.1** に
なる。標本期間の mid は 197〜1254 でこの境界をまたぐため、0.01 で固定すると
1000 超の日だけ距離が 10 倍に出る。本レポートは価格に応じてティック幅を切り替えている。

## 3. 説明変数が確定する時刻(先読みをしていないことの説明)

| 条件 | いつ確定するか | 作り方 |
|---|---|---|
| ① queue | 発注の瞬間 | 価格水準ごとに「open で +数量、終端で −数量」を行順に累積し、自分の行の直前の値から自分の数量を引く |
| ② size | 発注の瞬間 | `orig_sz` をそのまま |
| ③ dist | 発注の瞬間 | `ts < t0` を満たす最後の bbo を使う(同一 ns の行には自分自身の発注が混じりうるので厳密に手前で切る) |
| ④ wallet | 発注の瞬間 | その口座の**その注文より前の**累計本数。標本の先頭から数え上げる |
| ⑤ vol | 発注の瞬間 | 1 秒格子の mid から作った直前 300 秒の実現ボラティリティ。`t0` が入る秒の **1 つ前**まで |
| ⑥ ofi | 発注の瞬間 | `[t0 − 1秒, t0)` の OFI を合計し、**前日**の平均 \|OFI\| で規格化。符号は「自分の注文へ価格を押し付ける向き」を正 |

目的変数は $`t_0`$ **以降**の生存・取消・約定なので、[予測の定義](../../predicting_definition.md)
でいう時間契約(説明変数の確定時刻 ≤ 目的変数の期間の開始時刻)を満たす。
層の区切りは**最初の 5 日**の分位から丸めて決め、全期間へ同じものを当てている。

## 4. 全体像

| | 値 |
|---|---:|
| 母集団 | 549,920,651 本(98 日) |
| 同一ブロックで消滅(寿命 0) | 10.45% |
| 寿命の中央値 | 565 ミリ秒 |
| 1 秒後に板に残っている | 39.1% |
| 60 秒後に板に残っている | 2.2% |
| 最終的に約定 | **0.915%** |
| 最終的に取消 | 99.08% |

発注から 1 秒後の時点で、取消ハザードは毎秒 0.499、約定ハザードは毎秒 0.0042。
**その瞬間に「取り消される」ほうが「約定する」より 118 倍起こりやすい。**

ハザードは**最初の 1 ブロック(0.06〜0.1 秒)で最も高く、そこを越えると経過時間とともに

というブロック粒度の見かけであって、実質的な意味はない。

また第 8 節 5 のとおり、この分類は標本の先頭から数え始めているので、
期間の最初の数日は古参の口座も「初回」に入る。

### ⑤ 直前 300 秒の実現ボラティリティ(vol)

| 層 | 本数 | 同一ブロック消滅 | 1 秒後の生存率 | 寿命の中央値 | 最終的に約定 | h_約定(1秒) | h_取消(1秒) | 前半 | 後半 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| -7.5bp | 15,725,136 | 5.5% | 61.7% | 2.47 秒 | 1.440% | 0.0035 | 0.286 | 1.584% | 1.353% |
| 7.5-13 | 29,976,762 | 6.7% | 56.8% | 1.55 秒 | 1.293% | 0.0042 | 0.315 | 1.255% | 1.325% |
| 13-20 | 73,214,046 | 7.7% | 48.7% | 927 ms | 0.984% | 0.0040 | 0.392 | 1.141% | 0.907% |
| 20-32 | 170,822,831 | 9.3% | 40.8% | 623 ms | 0.810% | 0.0039 | 0.486 | 1.024% | 0.744% |
| 32-54 | 170,098,687 | 11.4% | 34.3% | 490 ms | **0.797%** | 0.0042 | 0.573 | 1.026% | 0.728% |
| 54-85 | 70,473,886 | 14.7% | 27.5% | 387 ms | 0.966% | 0.0052 | 0.663 | 1.333% | 0.832% |
| 85bp+ | 19,597,255 | 16.1% | 25.2% | 355 ms | 1.425% | 0.0077 | 0.707 | 1.871% | 1.269% |

**U 字**である。最終約定率は静かなとき 1.440%、中程度で 0.797%、荒れたとき 1.425%。
これを「ボラティリティは約定率に効かない」とまとめると誤りで、2 つの力が別々に
働いている。

- **取消ハザードは単調に増える**(毎秒 0.286 → 0.707)。荒れるほど速く引っ込める
- **約定ハザードも増える**が、増え方は中程度の帯でいったん頭打ちになる
  (0.0035 → 0.0039 → 0.0077)

生存率は単調に下がる(1 秒後 61.7% → 25.2%)。荒れた場では「約定しやすさ」も
「引っ込められやすさ」も上がり、後者のほうが速く上がるので、中程度の帯で
最終約定率が底になる。

### ⑥ 直前 1 秒の OFI(ofi)

符号は「価格が自分の注文へ向かってくる向き」を正にしてある(買い指値なら OFI が負、
売り指値なら OFI が正のとき「順」)。

| 層 | 本数 | 1 秒後の生存率 | 寿命の中央値 | 最終的に約定 | h_約定(1秒) | 距離を揃えた h_約定(0.1秒) |
|---|---:|---:|---:|---:|---:|---:|
| 逆 2以上 | 64,365,315 | 31.9% | 439 ms | 0.743% | 0.0040 | 0.0157 |
| 逆 1-2 | 52,247,559 | 31.9% | 439 ms | **0.710%** | 0.0039 | 0.0184 |
| 逆 0.3-1 | 85,077,207 | 34.5% | 485 ms | 0.786% | 0.0041 | 0.0216 |
| 逆 0-0.3 | 89,482,848 | 41.0% | 638 ms | 1.005% | 0.0046 | 0.0255 |
| 流量なし | 12,372,448 | 54.8% | 1.38 秒 | 1.024% | 0.0025 | 0.0141 |
| 順 0-0.3 | 82,477,653 | 44.1% | 744 ms | **1.104%** | 0.0048 | 0.0409 |
| 順 0.3-1 | 71,929,524 | 41.5% | 649 ms | 0.989% | 0.0043 | 0.0524 |
| 順 1-2 | 41,828,340 | 41.2% | 634 ms | 0.925% | 0.0039 | 0.0556 |
| 順 2以上 | 50,138,529 | 42.5% | 678 ms | 0.960% | 0.0038 | **0.0574** |

**ここは 2 つの読み方が違う結論を出す。**

最終約定率だけを見ると、最大 1.104%(順 0-0.3)対 最小 0.710%(逆 1-2)で 1.6 倍、
しかも「順 2以上」は「順 0-0.3」より低いので単調ですらない。「OFI は約定率にあまり
効かない」と結論したくなる。

しかし**距離を揃えて発注 0.1 秒後の約定ハザードを見ると、9 層が完全に単調に並び、
逆向きの端から順向きの端まで 3.6 倍(0.0157 → 0.0574)開く。**

差が消えて見えた理由は 2 つある。

1. **寿命が違う。**「流量なし」の注文は 1 秒後も 54.8% 残っており、寿命の中央値は
   1.38 秒。長く残るぶん約定を拾うので、最終約定率が高く出る。
2. **効果が短命である。** 1 秒後の約定ハザードでは 9 層の差は 0.0038〜0.0048 に
   縮んでいる。直前 1 秒の流量が語るのは、そのあと**数百ミリ秒**のことでしかない。

## 6. 距離を揃えた対照(交絡)

距離は他の 5 条件すべてと強く相関する。周辺の層別だけを見ると「数量の効果」が
実は「距離の効果」ということが起こる。そこで**最良気配から 10 ティック以内に
置かれた注文だけ**に絞って同じ層別をやり直した(検算図の右列と下段)。

| 条件 | 周辺での最大 ÷ 最小 | 距離を揃えたときの最大 ÷ 最小 |
|---|---:|---:|
| ① queue(先頭 ÷ 100-300) | 4.7 倍 | 8.4 倍(3.933% ÷ 0.466%) |
| ② size(最小 ÷ 最大) | 39 倍 | 20 倍(8.968% ÷ 0.439%) |
| ④ wallet(初回 ÷ 10万+) | 81 倍 | 51 倍(83.782% ÷ 1.644%) |
| ⑤ vol(85bp+ ÷ 32-54) | 1.8 倍 | 2.1 倍(3.678% ÷ 1.757%) |
| ⑥ ofi(順 0-0.3 ÷ 逆 1-2) | 1.6 倍 | 2.2 倍(2.826% ÷ 1.305%) |

**5 条件すべてで効果は残る。**②(数量)と④(口座)は距離を揃えると弱まるので、
周辺の値には距離による水増しが含まれていた。①(キュー位置)⑤⑥はむしろ強まる。
距離を揃えた母集団では約定率の水準そのものが 3〜4 倍上がる(全体 0.915% に対し、
10 ティック以内では層により 0.4〜9%)。

**層別の仕組み自体は差を作っていない。**

### 前半・後半

標本を発注日で 2 分割し、各層の最終約定率を別々に出した(第 5 節の表の右 2 列)。
①②④⑤⑥は**順序が両方の期間で保たれる**。破れるのは①の 300+ 層と③の 1001+ 層

### 既存レポートとの食い違い

同じリポジトリの [置いた指値が約定する確率](mu_fill_rate_report.md)(標本 10 日)は
「**効くのは水準よりキュー位置**」と結論している。本レポートは 98 日で
「**距離のほうがキュー位置より大きく効く**」(距離 28 倍 対 キュー 4.7 倍)としており、
表面上は逆である。**隠さず並べておく。**理由は 3 つあり、実際には矛盾していない。

1. **キュー位置の測り方が違う。** 向こうは「自分より前にいる注文の**本数**」、
   こちらは「前にある**数量**(契約)」。1 本 100 契約の先客と 1 本 0.1 契約の先客を
   同じ「1 本」と数えるかどうかで効果の見え方が変わる。
2. **距離の帯の上限が違う。** 向こうは「50 ティック以上」で打ち止めだが、この銘柄の
   距離の中央値は 82 ティックで、**注文の過半はその外側にある**。本レポートは
   1001+ まで刻んでおり、大きな差はまさに 50〜1000 の範囲で開く
   (51-100 で 0.212%、101-300 で 0.160%)。50 で切ると効果を 3 倍程度に見誤る。
3. **標本が 10 日と 98 日で、しかも 10 日は市場開設直後である。** 本レポートの
   前半・後半の比較でも水準は 1.157% 対 0.827% と動く。

### ★ `build_fill_rate.py` を全 99 日で走らせるときの注意

向こうのスクリプトは `TICK = 0.01` を定数で持っている。第 2 節のとおり
Hyperliquid の価格は有効数字 5 桁なので、**mid が 1000 以上の日はティック幅が 0.1**
になる。この銘柄では

- mid が 1000 以上だった bbo 観測は **全体の 25.6%**
- 日で見ると **27 日(2026-06-01 〜 2026-07-06)**が該当

したがって 10 日の暫定版(標本は 2026-05-04〜05-13、mid は 545〜600)では問題ないが、
**全 99 日へ広げるとその 27 日だけティック水準が 10 倍に出る。**
`build_fill_rate.py` を全期間で走らせる前に `tick_of(px)` 相当の切り替えを入れること。

### 多重比較の規模

13 系統の層別 × 計 96 層 × 31 の時間ビン × 2 つの原因 = **5,952 セル**を出している。
個別のセルに p 値は付けていない。標本が 5.5 億本あるので、ほとんどのセル差は
形式的には「有意」になる。判断の根拠は p 値ではなく、
**(a) 効果の大きさ、(b) 層をまたいだ単調性、(c) 前半・後半での再現**の 3 つに置いた。
この 3 つが揃わない箇所(①300+、③1001+)は本文で名指しして除いてある。

## 8. この結果が言っていないこと

1. **因果ではない。** これは条件付き分布であって、「自分が前に並ぶ位置を選べば
   約定率がこうなる」という話ではない。遠くに置く注文は、遠くに置きたい理由
   (在庫調整、保険、時間をかけたい執行)を持つ主体が出している。距離を変えれば
   その主体の他の性質も一緒に変わる。とくに④の口座別の差は、
   「口座を変えれば約定率が変わる」のではなく「取り消さない主体は約定する」
   というほとんど同語反復に近い関係を含む。
2. **距離は他の 5 条件すべてと相関する。** 第 6 節の距離を揃えた対照を必ず併せて
   読むこと。周辺の値だけを引用しないこと。
3. **板の厚みは部分約定を反映していない。** `orig_sz` を足して `orig_sz` を引く
   方式なので、部分約定で減った分は反映されない。約定するのは全体の 0.9% なので
   影響は小さいが、キューの先頭付近ではその 0.9% が集中する。①のキュー位置は
   その分だけ過大に出ている。
4. **同一ブロック内の順序は決められない。** L1 は `(ts, oid, 状態の論理順)` で
   並んでいるので、同じブロック内の別々の注文の前後関係は oid 順という恣意的な
   ものになる。1 ブロックあたり 6.5 行なので、キュー位置にはこの分の誤差が乗る。
5. **口座の累計本数は標本の先頭から数えている。** 期間の最初の数日は、実際には
   古参の口座でも「初回」に分類される。④の初回層(14,186 本)はこの影響を
   最も受けやすい。
6. **OFI の規格化は前日の平均 \|OFI\| を使う。** 標本初日だけはその日自身の値を
   使っている(98 日のうち 1 日)。
7. **1 銘柄(xyz:MU)の結果である。** 銘柄横断の比較は別途行う。

## 9. 再現手順

```bash
uv run python scripts/inventory_s3.py --refresh --coin xyz:MU
uv run python scripts/fetch_bbo.py --coin xyz:MU
uv run python scripts/fetch_l1.py --coin xyz:MU
uv run python scripts/fetch_l1_extra.py --coin xyz:MU   # 口座 ID と欠測時間帯
uv run python scripts/build_hazard.py --coin xyz:MU
uv run python scripts/plot_hazard.py --coin xyz:MU
```

`build_hazard.py --calibrate` を付けると、層の区切りを決めるための分位が出る。
`build_hazard.py` は 98 日分で約 26 分かかる(手元 16GB 機)。

生成される数値データ:

| ファイル | 内容 |
|---|---|
| `data/hazard_cells_<coin>.parquet` | 条件 × 層 × 時間ビン × 原因 の計数(生の集計) |
| `data/hazard_cells_half_<coin>.parquet` | 同じものを前半・後半に分けたもの |

| `data/hazard_summary_<coin>.csv` | 層ごとの要約(本レポートの表) |
| `data/hazard_strata_<coin>.csv` | 層ごとの件数と粗い約定率 |
| `data/hazard_diag_<coin>.csv` | 日ごとの検算(孤児・欠測・繰越・クロス) |
